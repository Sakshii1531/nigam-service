# payments-wallet

`Payment` + `WalletLedger` (Nigam Coins) are built (Phase 5). **Not a Mongo transaction** — the local dev mongod is standalone, not a replica set, and the user chose not to convert it rather than build around that assumption; see `../../../docs/DATA_MODEL.md` Phase 5 addendum for what this trades off. Instead: `wallet.service.js`'s `redeemCoins`/`creditCoins` are atomic at the single-document level (`findOneAndUpdate` with a balance guard), which is what actually matters for the "wallet balance consistent under concurrent requests" exit criterion (`tests/wallet.test.js`) — multi-document atomicity across payment+wallet+order is still a real, documented gap. See BACKEND_CONTEXT.md §3.10.

`paymentGateway.js` is real Razorpay (post-Phase-15, user-confirmed choice + credentials) — `createRazorpayOrder()` + `verifyRazorpaySignature()`, the standard Checkout.js create-then-verify flow (no legitimate gateway lets a server charge a customer with zero interaction). Both `buy-commerce/order.service.js` and `technician/job.service.js` call these directly rather than through this module's own routes — there's no generic `/payments/*` endpoint, since a Razorpay order always belongs to a specific Order or Job and each has its own `/verify-payment` route. See the Post-Phase-15 addendum in `../../../docs/DATA_MODEL.md` for the full flow.
