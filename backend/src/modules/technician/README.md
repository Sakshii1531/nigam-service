# technician

Phase 6 — the largest, highest-risk module (mirrors `ActiveJob.jsx`, the biggest file in the frontend). `Technician` profile (+ payout methods), `Job` (ServiceRequest/Booking joined with tech-facing metadata) and its linear happy-path state machine (`JOB_STEP_TRANSITIONS`, `revisit` sub-flow deliberately deferred), tech-side `Claim` (manual + auto-raised FOC claims), `TechInventoryItem` (read) + `PartOrder`, `EarningsTally` + `Payout`, read-only Academy content (`Course`/`TrainingGuide`/`TechBlog`) + `Announcement`. See BACKEND_CONTEXT.md §4 and `../../../docs/DATA_MODEL.md`'s Phase 6 addendum.

Every `Job.activeStep` transition drives the linked `ServiceRequest.status` through its own state machine in lockstep (`job.service.js`'s `transitionStatus` calls) — `acceptJob` → `Engineer Accepted`, `startTravel` → `Visit Scheduled`, `arrive` → `Engineer Reached`, `submitDiagnosis` → `Diagnosis Done`, `submitSpareParts` (if any part is checked) → `Spare Required` → `Spare Ordered` → `Spare Received`, `confirmRepairComplete` → `Repair Completed`, `collectPayment` → `Customer Confirmation`. `Closed` requires a separate customer-confirmation action, out of this module's scope.
