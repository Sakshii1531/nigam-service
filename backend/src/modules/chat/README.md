# chat

Phase 9. `Conversation` / `Message`, scoped per service-request. This module (`conversation.service.js`, `message.service.js`, `chat.routes.js`) is the **read-only REST surface** (list conversations, get one, read message history) — sending happens exclusively over the socket (`../../sockets/chat.gateway.js`'s `send-message` event), and there's no public "create conversation" endpoint: `getOrCreateConversation()` is called as a side effect of `technician/job.service.js`'s `acceptJob()`, where customer+technician+serviceRequest are already a verified real pairing, not arbitrary client-supplied ids. Phone numbers are masked (`auth/otpProvider.js`'s `maskIdentifier`) for both participants in every REST response — real masked *calling* (a telephony relay) needs an actual provider integration and is out of scope, same class of gap as OTP/SMS (BACKEND_CONTEXT.md §9). See BACKEND_CONTEXT.md §3.13 and `../../../docs/DATA_MODEL.md`'s Phase 9 addendum.
