# notifications

Phase 9. `notification.service.js`'s `emit(event, payload)` is called from domain services as a side effect (booking created/technician assigned — `booking/booking.service.js`; payment success/service completed — `technician/job.service.js`'s `collectPayment()`; claim approved — `super-admin/claim.service.js`; escalation raised — `super-admin/escalation.service.js`) rather than those services constructing `Notification` docs themselves — one place owns what each event actually says. **Never throws**: an unknown event or a template/DB failure logs and returns `null`, so a bug in a notification template can never break the domain action that triggered it. Real-time delivery pushes to the recipient's `user:<id>` socket room (or `broadcast:<role>` for platform-wide ones) via `../../sockets/io.js`'s `getIO()`; `GET /notifications` is the REST fallback/history read. **Device push has two paths**: `deliverExternal()` resolves one `User` and covers push/SMS/WhatsApp for personally-addressed notifications, while `deliverBroadcastPush()` fans a role-wide push out across the whole audience — it pages users by `_id` (never `skip`), drops explicit opt-outs via a single `NotificationPreference` query rather than one lookup per user, and chunks tokens into 500s because `sendEachForMulticast` rejects more than that in one call. Only `sendAdHocPush()` (the console composer, where a human picked the audience) triggers the broadcast fan-out, and it does so **detached** — the admin's request returns before a large fan-out finishes; `awaitPendingDeliveries()` is the hook tests and shutdown use to wait it out. `emit()`'s broadcast templates (escalation, brand warranty claim) stay in-app on purpose: an ops escalation should not ring every phone on the platform. Broadcast notifications (`recipient: null`, `broadcastRole` set) have a single shared `read` flag, not a per-recipient read receipt — `markRead()`/`markAllRead()` only ever touch personally-addressed ones, a documented schema limitation, not silently mishandled. See BACKEND_CONTEXT.md §3.12 and `../../../docs/DATA_MODEL.md`'s Phase 9 addendum.
