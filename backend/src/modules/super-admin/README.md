# super-admin

Phase 8. Platform-level entities not owned by any brand, all under `/api/v1/super-admin/*` (super_admin-only) except `/api/v1/cms/*` (public reads, super_admin-only writes): `Brand`, `City`, `ServicePartner`, `ASM`, the real weighted auto-assignment engine (`../shared/assignmentEngine.js`, replaces the Phase 4 stub), `LiveTracking`, `Escalation` (platform-scope only — brand-scope has no route yet), `AuditLog` (+ `../shared/auditLog.js`'s `logAudit()` helper, wired into a couple of actions as a proof of concept, not comprehensively), `SparePartCatalog`, `PlatformSettings` (extended with loyalty config fields), CMS/app-customization (`Banner`/`Story`/`Video`/`Advertisement`/`CMSPage`/`AppSetting`), loyalty config authoring (`LoyaltyMilestone`/`Membership`/`SpinWheelConfig`, models live in `rewards-loyalty/`), platform-wide `Role`/`Permission` RBAC, and cross-role `User` management. See BACKEND_CONTEXT.md §6 and `../../../docs/DATA_MODEL.md`'s Phase 8 addendum.

**Deliberately deferred, not built this phase**: the Finance sub-module (`BillingTransaction`, `Revenue`, `PartnerPayout`, `GatewayTransaction`) — all four models already exist from Phase 1, but none of them have a real system-generated data source anywhere in the codebase yet (no commission-calculation job, no partner-earnings ledger, no gateway webhook integration). See the DATA_MODEL.md addendum for the full reasoning.

**Phase 11 addition**: `exchangeRequest.routes.js` — a physical-inspection approval surface (`GET /`, `GET /:id`, `PATCH /:id/status`) for `warranty-amc-exchange`'s `ExchangeRequest`, added as a security fix (see that module's README and the Phase 11 DATA_MODEL.md addendum) rather than a planned Phase 8 feature. Same "platform-wide stand-in authority, no real brand/warehouse scoping yet" shape as `claim.routes.js` from Phase 9.
