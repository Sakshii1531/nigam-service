# sockets

Phase 9. `index.js`'s `initSockets(httpServer)` creates the `Server`, applies `socketAuth.js` (same JWT the REST API uses, via `socket.handshake.auth.token`), auto-joins every connected socket to its own `user:<id>` room (+ `broadcast:All`) for `notifications/notification.service.js`'s `emit()` to push into, then registers `chat.gateway.js` (conversation-scoped messaging, room-per-conversation) and `tracking.gateway.js` (live GPS feed for super-admin Tracking.jsx, room `tracking:super-admin`). `io.js` is a tiny getter/setter singleton so domain services can push a socket event without importing a gateway file (avoids a circular-import tangle between `src/sockets/` and `src/modules/`). Wired into `server.js`, which now wraps the Express app in a raw `http.Server` instead of calling `app.listen()` directly. See `../../../docs/DATA_MODEL.md`'s Phase 9 addendum — this is the module the exit criterion ("two connected Socket.IO test clients exchange a message scoped to one conversation and don't leak into another") is about; verified in `../../tests/sockets.test.js`.
